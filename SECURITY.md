# Security Policy

## Supported Versions

The project is pre-1.0. Security and data-integrity fixes are handled on the main development line until formal releases begin.

## Reporting A Vulnerability

Please do not open a public issue for vulnerabilities involving:

- credential exposure;
- unsafe publication of restricted source material;
- external-model processing of disallowed source text;
- corruption of canonical research records;
- bypasses of release, schema, or immutability guardrails.

Use GitHub private vulnerability reporting after the repository is published, or contact the maintainers directly until that feature is enabled.

## Data Integrity Issues

Research-data integrity problems are treated seriously even when they are not traditional software security vulnerabilities. Report anything that could cause:

- generated output to be mistaken for canonical evidence;
- reference annotations to be overwritten;
- released IDs to be silently changed;
- restricted or copyrighted source material to be exposed;
- claims to lose their evidence-chain provenance.
